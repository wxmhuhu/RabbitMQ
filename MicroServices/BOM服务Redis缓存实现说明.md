# BOM 服务 Redis 缓存实现说明

## 概述

本文档说明了如何通过 RedisHelper 帮助类实现 GetBomAsync 方法的 Redis 缓存功能，以提高 BOM 查询的性能和用户体验。

## 实现的功能

### 1. GetBomAsync 方法缓存优化

- **缓存键生成**: 根据搜索条件（页码、页大小、BOM 编号、产品名称、BOM 版本）生成唯一的缓存键
- **缓存策略**: 使用 RedisHelper.GetRedisList 方法实现智能缓存
- **缓存时间**: 设置 1 小时（3600 秒）的缓存过期时间
- **数据一致性**: 在数据变更后自动清除相关缓存

### 2. GetBomTreeAsync 方法缓存优化

- **树形结构缓存**: 为完整的 BOM 树形结构和子树结构分别设置缓存
- **缓存键设计**: 根据 ID 参数生成不同的缓存键（完整树：BOM*Tree_0，子树：BOM_Tree*{id}）
- **性能提升**: 避免重复构建复杂的树形结构

### 3. 缓存管理机制

- **自动清除**: 在创建、更新、删除 BOM 后自动清除相关缓存
- **批量清除**: 使用通配符模式清除所有 BOM 相关的缓存键
- **异常处理**: 缓存清除失败不影响主业务逻辑

## 技术实现细节

### RedisHelper 使用方式

```csharp
// 使用RedisHelper缓存分页数据
var cachedResult = await helper.GetRedisList(cacheKey, async () =>
{
    // 数据获取逻辑
    return dtoList;
}, 3600); // 缓存1小时
```

### 缓存键命名规范

- **分页查询**: `BOM_List_{PageIndex}_{PageSize}_{BomCode}_{ProductName}_{BomVersion}`
- **树形结构**: `BOM_Tree_{id}` (id 为 0 表示完整树)

### 缓存清除策略

```csharp
private async Task ClearBomCache()
{
    try
    {
        // 清除所有BOM相关的缓存键
        var keys = await redis.KeysAsync("BOM_*");
        if (keys != null && keys.Any())
        {
            await redis.DelAsync(keys.ToArray());
        }
    }
    catch (Exception)
    {
        // 缓存清除失败不影响主业务逻辑
    }
}
```

## 性能优势

### 1. 查询性能提升

- **首次查询**: 从数据库获取数据并缓存到 Redis
- **后续查询**: 直接从 Redis 获取缓存数据，响应时间显著降低
- **并发查询**: 多个相同条件的查询共享缓存，减少数据库压力

### 2. 系统资源优化

- **数据库连接**: 减少重复的数据库查询操作
- **内存使用**: 利用 Redis 的高性能内存存储
- **网络开销**: 减少数据库服务器的网络传输

### 3. 用户体验改善

- **响应速度**: 缓存命中时响应时间从毫秒级降低到微秒级
- **数据一致性**: 智能的缓存更新策略确保数据准确性
- **系统稳定性**: 减少数据库压力，提高系统整体稳定性

## 使用注意事项

### 1. 缓存配置

- **过期时间**: 根据业务需求调整缓存过期时间（当前设置为 1 小时）
- **内存管理**: 监控 Redis 内存使用情况，避免内存溢出

- **及时清除**: 数据变更后立即清除相关缓存

- **错误处理**: 缓存操作失败时的降级策略
